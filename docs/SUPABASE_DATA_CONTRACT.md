**Audit source:** legacy repository main, especially supabase.js and the SQL migrations listed below.  
**Status:** partial source-code audit, not a live database introspection. This is enough to define investigation targets, not permission to ship production queries yet.

## 3. Confirmed relationships and semantics

### Groups and memberships
- bandplan_groups.id is UUID primary key, generated by gen_random_uuid().
- name is required; normalized_name is generated from lower(trim(name)); name length is 3–50 characters.
- owner_id references auth.users(id) with ON DELETE CASCADE.
- Unique index exists on normalized_name.
- bandplan_group_members has group_id and user_id, both cascading foreign keys; composite primary key (group_id,user_id).
- Index exists on group_members.user_id.
- One user can belong to multiple groups.
- Membership list RPC returns group_id, group_name, owner_id, joined_at, role.
- Active group is stored in bandplan_user_state.state.activeGroupId.

### Shared state
- bandplan_group_state has group_id as primary key referencing groups(id) with cascade delete.
- state is JSONB, not null, default empty object.
- updated_at is timestamptz, not null, default now().
- RLS is enabled. Initial migration grants authenticated members select/insert/update and revokes delete.
- Realtime publication includes bandplan_group_state.

### Group data records
- Legacy client loads songs/events/setlists from each table's data JSON payload, filtered by active group_id.
- The JSON payload contains its own id; the table key is the composite group_id + id in the sync upsert behavior.
- Sync sends deltas, not full replacement snapshots, to avoid overwriting unrelated newer records.
- Deletes are explicit ID arrays in the sync RPC.

### Participation
- Valid statuses: yes, maybe, no; null/empty status clears the user's status.
- Participation is normalized in bandplan_event_participation and hydrated into event JSON for UI.
- Current RPC accepts event id, status, optional client timestamp, and optional group id.
- Server clamps client timestamps to a bounded window and applies last-write-wins.
- Participation changes are group-scoped and user-scoped.

### Personal state
- Personal songs and personal setlists are stored separately from group songs/setlists inside the user's state payload.
- Personal settings are also written to bandplan_accounts.personal_settings and merged with user state by the legacy client.
- Group-owned songs/events/setlists are not the same records as personalSongs/personalSetlists.

## 4. RPC inventory — signatures from latest migration

Source: supabase/migrations/20261031130000_multi_group_workspaces.sql. These signatures should be rechecked against the live database before implementation.

| RPC | Signature / return | Observed behavior |
|---|---|---|
| bandplan_get_my_groups | () → table(group_id uuid, group_name text, owner_id uuid, joined_at timestamptz, role text) | Lists every membership for auth.uid() |
| bandplan_set_active_group | (p_group_id uuid) → uuid | Verifies membership and writes activeGroupId into user state |
| bandplan_get_my_group | () → table(group_id uuid, group_name text) | Returns active group if valid, otherwise earliest membership |
| bandplan_create_group | (p_name text, p_display_name text, p_roles text[] default '{}') → table(group_id uuid, invite_code text) | Creates group, owner membership, account profile, invite, initial group state; activates group |
| bandplan_join_group | (p_code text, p_display_name text, p_roles text[] default '{}') → table(group_id uuid, group_name text) | Validates invite and adds membership without removing other groups |
| bandplan_get_invite_code | () → text | Returns or creates an invite code for the selected/available group |
| bandplan_create_group_and_invite | (p_name text, p_display_name text, p_roles text[] default '{}', p_group_id uuid default null) → table(group_id uuid, group_name text, invite_code text) | Gets/creates invite for selected group |
| bandplan_leave_group | (p_group_id uuid default null) → table(group_id uuid, group_name text) | Removes only requested membership; owner handoff and remaining-group selection rules apply |
| bandplan_rename_group | (p_name text, p_group_id uuid default null) → void | Renames a group the user belongs to |
| bandplan_sync_group | (p_songs jsonb, p_events jsonb, p_setlists jsonb, p_roster jsonb, p_display_name text, p_roles text[], p_personal_settings jsonb, p_delete_songs text[] default '{}', p_delete_events text[] default '{}', p_delete_setlists text[] default '{}', p_group_id uuid default null) → void | Writes group-scoped JSON deltas and account profile/settings |
| bandplan_set_event_participation | (p_event_id text, p_status text, p_updated_at timestamptz default null, p_group_id uuid default null) → jsonb | Writes per-user participation with last-write-wins |

Other observed RPC:
- bandplan_delete_my_account() → void (signature and behavior from 20261005000100_fix_account_deletion_foreign_keys.sql; inspect full migration before implementing).

All these functions are SECURITY DEFINER in the latest migration and have EXECUTE revoked from public/anon, granted to authenticated. Do not rely on function names alone; verify search_path, internal checks, and live grants.

## 5. Realtime subscriptions observed
Legacy client subscribes to:
- bandplan_user_state filtered by user_id.
- bandplan_songs, bandplan_events, bandplan_setlists filtered by group_id.
- bandplan_group_state filtered by group_id.
- bandplan_groups filtered by id.
- bandplan_group_members filtered by group_id.
- bandplan_accounts for current member IDs.
- bandplan_event_participation changes filtered by group_id, plus a broadcast channel for participation.

The exact publication configuration and Realtime authorization for every table still need audit.

## 6. RLS and security findings
- Initial group migration enables RLS on bandplan_groups, bandplan_group_members, and bandplan_group_state.
- A private helper checks membership and is SECURITY DEFINER.
- Initial policies allow members to read their groups/memberships/shared state and insert/update shared state.
- A later hardening migration defines account ownership and group-member policies for songs, events, setlists, and invites.
- Profile directory access was tightened in 20261004204213_tighten_profile_directory_access.sql.
- This audit has not yet captured every policy expression or table grant. Do not consider the RLS review complete.

## 7. Offline contract observed in legacy browser client
- IndexedDB database name: bandplan-cloud-v1, schema version 3.
- Stores include snapshots, sync_queue, participation_queue, and event_offline_songs.
- Cache is scoped by account; pending sync and participation changes are durable.
- The Flutter app must implement platform-appropriate storage, not copy browser IndexedDB.
- Queue format, idempotency, retry, merge rules, and migration of existing offline-only changes need a separate design. Do not promise cross-device recovery of unsynced browser-local changes.

## 8. Unknowns that block production repository implementation
- Full DDL for bandplan_user_state, bandplan_accounts, bandplan_songs, bandplan_events, bandplan_setlists, bandplan_event_participation, and bandplan_group_invites.
- All constraints, indexes, triggers, RLS expressions, grants, and Realtime publication entries for those tables.
- Exact JSON payload schemas and optional/legacy fields for songs, events, setlists, profiles, and personal settings.
- Exact auth metadata keys and redirect/deep-link URLs.
- Live RPC signatures and behavior versus latest migration source.
- Whether all currently used columns are exposed through the Supabase Data API.

**Implementation rule:** until these unknowns are resolved, Flutter may define draft domain interfaces but must not issue guessed production writes or schema changes.
